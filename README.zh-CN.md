Boat Watch 是一个以本地数据为主、用于照看真实船只的 Android 工具：可以做锚警、理解 NMEA 仪表、记录航程、绘制个人水深图，也能保存下次还想去的锚地。

只有手机时，锚警仍可直接使用系统 GPS；船上有 NMEA 0183 时，可以接入船位、艏向、风和水深，同时明确显示每个数值来自哪里。锚警、航程、地图和数据共享各自管理状态，不会因为开启一个功能就偷偷改掉另一个功能。

> **安全提示：** Boat Watch 只能作为辅助工具，不能替代正规的锚泊值守、航海判断、官方海图、测深仪或独立报警设备。GPS、供电、Wi-Fi、NMEA 设备和 Android 后台运行都可能失效。

## 它能帮你做什么

### 持续看住锚泊中的船

- 已知锚位时直接设置中心；不知道中心时，可以让 App 随船摆动，保守学习可能的锚中心。
- 普通使用可以选系统 GPS 或通过验证的 NMEA GPS。NMEA 没有连接并持续提供新鲜有效定位时，界面和内部逻辑都不能选择它。
- 地图会显示报警圈、船的方向和最近 24 小时轨迹；新轨迹保持清楚，旧轨迹经过足够距离后才逐渐淡化。
- 监控过程中可以调整报警半径；暂停不会丢失这次锚泊，之后可以原地恢复；只有 **起锚** 才会永久结束 session。
- 走锚时会同时出现循环警报、通知和 App 内操作弹窗。确认报警可以让持续风险稍后再提醒；调整范围、暂停或起锚会结束当前响铃状态。
- NMEA 数据可用时，还可以选择浅水、深水、风速和风向突变警戒。

### 在布防前和监控中确认系统是否可靠

- **布防前检查（Watch Preflight）**会检查定位新鲜度和精度、NMEA、通知权限、警报是否可听见、电池与后台限制、供电、网络、存储和声呐。
- **持续监控健康（Watch Health）**会在 session 中继续显示相同的安全状态。
- NMEA 意外断开时不会偷偷切到另一个 GPS 数据源。
- 环形 Incident Log 保存最近的安全状态变化；默认隐去原始 NMEA 和精确位置的 Support Bundle 可以用来排查“昨晚为什么报警”。

### 接入和分享 NMEA，但不混淆两种用途

- 可作为 TCP 客户端或 UDP 监听器。只有真正收到可用 NMEA 后，**测试、保存并连接**才会成功。
- 可以查看原始语句、解析值、checksum 错误和连接健康。
- 支持常见 talker ID 下的 RMC、GGA、GLL、VTG、ZDA、HDG、HDM、HDT、DPT、DBT、MWD 和 MWV。
- **向船载网络发送手机 / App 数据**会持续发布当前所有有效的本机自有值，例如手机 GNSS、对齐后的手机艏向、已确认的 Trip 运动、气压和明确由 App 推算的风。它不会把刚从船上收到的仪表数据转发回去，也不会因为船网出现同类字段而自动让位；由接收端仪表选择使用哪个来源。默认复用现有全双工输入连接；独立网关 TCP/UDP 只作为用户明确选择的高级路线。
- **KC-2W 实船注意：**完整分享手机 / App 数据时，NMEA 0183 侧应使用 38400 baud。实船已确认 4800 在 Raymarine 加入后会成为瓶颈，造成 DataList 间歇消失和 `NO HEADING`；只把 KC-2W 改成 38400 后即恢复稳定。
- **在本机提供 NMEA 服务**是完全独立的功能，供可信 LAN/VPN 上的另一台手机、平板或 dashboard 连接。它有自己的端口、启动/停止状态、客户端数量和生成/实际发送原始数据；启动或停止它都不会改变“向船载网络发送手机 / App 数据”。
- 需要时可把可信 NMEA 船位代理为 Android 全局模拟位置；App 会给出开发者设置指引，并阻止数据回环。
- 一条合法语句中缺少某个字段，只表示“这个字段本次没有更新”，不会把历史值判成非法或直接清空。水深、风、艏向和航速会保留原始接收时间，并明确从**实时**变成**保持值**再变成**已过期**；安全警戒仍然执行各自更严格的新鲜度门槛。

### 记录航程，但不改变锚警安全逻辑

- **监控 → 航程监控**通过独立的 Vessel Data Hub 显示 NAV、帆航、运动和天气仪表。Hub 的 AUTO 回退绝不会改变锚警 session 已锁定的 GPS 来源。
- 可以开始、暂停、继续和结束本地航程。开始前会显示各项仪表是否可用；确实缺失的数据会留下空档，不会被补成虚假的零值。
- 手机横倾/纵倾是 Trip Watch 的可选功能：让屏幕平面与船体参考平面平行，选择指向船艏的一边后确认。这里只映射坐标轴，不会把已经横倾的船错误归零。拿起手机前由用户主动暂停姿态，放回后重新确认；手机气压计始终独立工作。
- 可以创建命名仪表盘，把自动发现的 NMEA 字段绑定成仪表；是否显示和是否按最高 2 Hz 写入航程互相独立，不会因此保存整条原始 NMEA。
- 已完成航程会生成完整航行轨迹、SOG/BSP、最快 500 米、同步航速—横倾分段、保守的航行角度与换舷观察、运动、水深/UKC、风、气压、来源切换、事件和航点报告。报告统计只会排除孤立的短时姿态尖峰；持续横倾、线性变化和 GPS 能证明的转向会保留。回放可按 SOG、BSP、横倾、TWS、AWS、运动或水深着色，并跳转到事件。
- 可导出 CSV、事件、航点、自定义数据、GPX、KML/KMZ、品牌截图或本地 AI 源数据 ZIP。只有水深参考面与已配置吃水兼容时才显示 UKC；航程 session 与锚泊 session 不能同时活动。
- 已完成的锚泊和航程都可在精确位置隐私提示后生成本地 **AI 源数据 ZIP**；App 不会自行上传这些文件。

### 使用地图、收藏锚地和水深

- 地图内可直接切换 **默认、卫星、航海**。锁定跟船时仍可临时拖动和缩放，随后自动回到船位；自由浏览则保留当前视野。
- 距离标尺会随当前纬度和缩放级别变化。点击尺子按钮会出现两个可拖动图钉，并以米或“海里 + 公里”显示直线距离；再次点击会清除图钉和测量结果。
- 可叠加新西兰区域 LINZ 本地水深、合法的非 Google 受限缓存，或用户有权使用的栅格 MBTiles。App 永远不会缓存 Google 瓦片。
- 收藏锚地后可以查看和编辑锚泊位置、参数与备注，打开全屏接近指引，或跳转 Google 地图。品牌分享卡有两个用途清楚的二维码：任何手机都能打开地图位置；Boat Watch 则可在用户预览并确认后导入更完整的本地资料。
- 接近明确收藏过的锚地时，可以打开直线距离与方位指引。NMEA 有可用 HDT/HDG 或可信的移动 COG 时可选“船方位”，否则使用“手机方位”。它不是航线规划，也不会判断航路是否安全。
- 真实个人声呐调查只接受**同一台已连接 NMEA server**提供的水深和船位；锚警选择的系统 GPS 不会移动真实测深点。
- 声呐调查支持不修正、手动潮汐修正或自动 LINZ 潮汐预测，并保留可离线查看的海图基准水深历史。

## 第一次使用

1. 授予精确定位和通知权限。
2. 打开 **设置 → 报警与通知**，试听警报并确认自己能听见。可以使用标准锚警声，也可以选择自定义音频文件。
3. 只用手机 GPS 时可以直接回到锚警地图；使用船载数据时，打开 **数据 → NMEA**，填写 TCP/UDP 端点，再点 **测试、保存并连接**。
4. 在 **数据 → 原始数据**确认这些数据确实来自你的船，而且仍在更新。
5. 回到锚警地图，选择地图样式，然后点击 **设置锚点**。
6. 完成布防前检查，选择已知中心或自动估算，再设置报警半径。
7. 夜间使用时请保持可靠供电，并检查 **设置 → 后台可靠性**，避免系统暂停 App。
8. 监控期间要有意识地使用 **调整范围、暂停、恢复、起锚**；收到警报后先检查船况，不要只关闭声音。

## 自动推测锚中心

一条直线倒车轨迹无法唯一决定圆心，所以 App 不会把一段 GPS 直线当成答案。它会根据水深、放链长度和船艏高度先建立一个故意偏大的可能中心范围，只有在多个相容位置圆盘、真正不同的方位扇区、反向运动和重复方向证据互相支持时才逐步缩小。艏向与风向只能增强候选，不能单独确认中心。高置信度候选也必须由用户接受后，才能替换工作中心。

数学、物理和实现细节见 [锚中心点推测算法](docs/ANCHOR_CENTRE_ESTIMATION.md)。

## 演示模式、语言与隐私

开发者演示模式用于在没有真实 NMEA server 时熟悉 App。每次新下锚都会先读取新鲜的系统 GPS 作为起点，再生成逐步放缆、带相关噪声的船舶轨迹和对应演示声呐。演示模式或演示 session 开启后，数据源会锁定，避免真实与模拟数据混在一起。

App 默认使用英文。欢迎页和设置中的语言列表支持 English、简体中文、繁體中文、日本語、Français 和 Español。

Session 和声呐调查保存在本机。只有打开锚地二维码扫描器时才会申请相机权限，画面也只在本机解码。项目没有账号、分析统计、广告或自建云端；只有用户主动导出或共享时，数据才会离开设备。

本地 V4 备份包含锚泊与航程 session、原始观测、航点、航程自定义字段、命名仪表盘、收藏锚地、船舶数据源与仪表布局偏好，以及手机船体安装校准。导入的 MBTiles 与自定义警报音频不进入备份；恢复时活动监控会进入安全的暂停状态，所有 GPS/NMEA 对外输出都不会自动重新开启。

两个 NMEA 产品在设置和运行时都彼此独立。“向船载网络发送手机 / App 数据”会持续发送当前所有有效的本机自有值，通常写入现有全双工连接；独立网关 TCP/UDP 只能作为明确开启的高级路线。“本机 NMEA 服务”则通过自己的监听端口向其他设备提供同类手机/App 数据，绝不转发船载输入流。来源优先级由接收端设备决定，不存在用户看不见的 App 备用关系。手机位置输出与“使用船载 NMEA 位置作为 App GPS”仍在逻辑上硬互斥。

## 编译、CI 与下载

需要 JDK 17 和 Android SDK 36。

```bash
./gradlew assembleDebug
```

主 Android workflow 负责构建和验证可下载的 Debug 产物。耗时的设备 story 集成测试与正式签名发布线互相独立；正式发布仍必须通过签名预检、单元测试、release lint、编译、校验和与启动 smoke。构建、Lint、模拟器、soak、签名或发布任务失败时，该次 Actions 运行会保留 30 天的 `FAILURE-*` 可下载诊断包，包含已有报告和设备 logcat，但不会包含 API 或签名密钥。当前 workflow 发布到 GitHub Release，不会自动上传 Google Play。

API 值不会提交到仓库。地图、LINZ 和正式签名需要哪些 GitHub Secrets，以及如何从本机安全复制，见 [CI Secrets 配置说明](docs/CI_SECRETS.md)。分支与发版关系见 [分支和发布说明](docs/BRANCHING_AND_RELEASES.md)。
